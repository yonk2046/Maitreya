## 4. 進出場怎麼算

### 4.1 現行引擎的三個缺陷(都要先修)

| # | 缺陷 | 影響 | 出處 |
|---|---|---|---|
| B1 | 成交價讀快照 `open`,晚上建的快照 `open` 是前一天的 | 91% 成交價非真實開盤 | EXEC-PLAN §7.1 |
| B2 | 每日 `golden.run(snaps[:i+1])` 重算整段歷史 | 成本近立方;整年 ~250 份快照跑不完 | §7.2 |
| **B3(新)** | **持倉股票一掉出當日選股範圍,引擎就 `continue`** —— 不更新峰值、不檢查任何出場條件,也無法成交;要等它重新上榜才可能出場 | **實測:163 筆交易中 146 筆有「掉榜期間」;持有日數的 53% 是掉榜狀態**。`chip_anchored_swing` 的 `main_force_sell` 出場 **0 次**(主力翻賣的股票本來就不會在買超榜上) | `core/paper_trading.py` 三個迴圈皆同:v1 `:180-183`、`:205-207`;v2 `:489`、`:503`;v3 `:678-684` |

B3 的意思:回測裡的停損/出場大多「看不到」股票最危險的那段 —— 主力倒貨時它正好掉出買超榜。**這可能讓所有現存回測數字系統性偏樂觀**(方向待 T1 修完實測)。本條應登記 FAILURE-MODE-INDEX 與 EXEC-PLAN §七。

**修法方向**:把「選股範圍」和「持倉追蹤」分開。持倉股票每天都要有價格與主力資料,不論是否在榜上。重建流程天然提供(持倉股票照抓分點);正式鏈上則需把持倉股票納入每日抓取範圍(另案)。

### 4.2 成交規則(提案)

| 事件 | 規則 | 理由 |
|---|---|---|
| 訊號 | 第 t 日收盤後、只用 ≤ t 且**當晚 19:00 前已公布**的資料 | 符合實際操作(晚上看訊號、隔天下單);防 look-ahead |
| 進場 | t+1 **真實開盤價**(按日期查) | 修 B1 |
| 進場受阻 | t+1 開盤 = 漲停價 → 視為**買不到**,不進場 | 日線看不出是否鎖死,保守處理 |
| 出場判斷 | 每日收盤檢查(含掉榜期間,修 B3) | 與現行策略語意一致 |
| 出場成交 | t+1 真實開盤;跳空低開就照低開價成交 | 真實滑價,不美化 |
| 出場受阻 | t+1 開盤 = 跌停價 → 賣不掉,順延到下一日 | 保守 |
| 停牌 | 無價格日持倉凍結、復牌首日開盤出場判斷 | |
| 除權息 | 除權息日依參考價調整進場價/峰值/成本錨,現金股利計入報酬 | 否則除息缺口會觸發假停損 |
| 成本 | 沿用凍結參數:`FEE_RATE=0.000855`、`FEE_MIN=20`、`TAX_RATE=0.003`(ETF 0.1%) | 不動凍結值 |
| 部位 | 沿用 `POSITION_SIZE=100000`;另外報一版「整張」(1000 股取整)看差異 | 現行可能用零碎單位 |
| 基準 | 發行量加權**報酬**指數(含息),逐筆同期間比 | 價格指數會低估大盤 |
| 期末 | 未平倉以最後收盤標記,另列 `end_of_data`,不混入已實現統計 | 沿用現行 |
